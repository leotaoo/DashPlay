# F50 换卡后 DuckDNS 域名访问排查记录

- 日期：2026-11-04
- 设备：ZTE F50，OpenWrt + DashPlay，512GB 原卡 → 256GB 新卡
- 域名：`hika-tesla.duckdns.org`
- 现象：换卡后大部分功能正常，但通过 DuckDNS 域名访问不了
- 性质：排查记录；F50 侧检查结果来自当时 SSH 实测，客户端侧原因需按第 5 节继续确认

---

## 1. 先看结论

**克隆本身没有把 DuckDNS 配置弄丢。** 当时 F50 上的状态是：

- DuckDNS 子域名和 token 都在；
- DuckDNS 记录状态 `record: ok`，地址 `100.96.0.1`；
- Let's Encrypt 证书有效，`phase: ready`；
- `dashplay` receiver 在运行；
- F50 能上网（`ping 1.1.1.1` 通）；
- F50 本机 DNS 能把 `hika-tesla.duckdns.org` 解析到 `100.96.0.1`。

所以问题不在“克隆把文件弄坏了”，而更可能在**客户端侧**：

1. 测试设备不在 F50 的 WiFi（`DVA`）上；
2. 客户端用了别的 DNS / DoH / 代理 / VPN，导致解析结果不对或被拦；
3. 特斯拉或手机缓存了旧的 DNS 记录；
4. 客户端把 `100.96.0.1` 当成“私有地址”过滤掉了（DNS rebind protection）。

DuckDNS 这个域名解析到的是 **`100.96.0.1`**，这是 F50 的**私有 LAN 地址**。它只对连在 F50 的 WiFi 上的设备有效，**不是公网远程访问入口**。从家里、公司或手机流量访问，解析到 `100.96.0.1` 也到不了——这是设计如此，不是换卡造成的。

## 3. 为什么 DuckDNS 域名会“访问不了”

### 3.1 这个域名指向的是私有地址

DashPlay 的 DuckDNS 设计是：域名解析到**车机要打开的那个地址**，在 F50 特斯拉模式下就是 `100.96.0.1`。`own_domain.py` 的注释也写明：

> DuckDNS takes a private address; a DNS server that filters those ("rebind protection") will not resolve the name.

也就是说：

- 车机连在 F50 的 WiFi `DVA` 上，解析到 `100.96.0.1`，能直接访问 F50；
- 手机/电脑不在 `DVA` 上，解析到 `100.96.0.1` 也到不了；
- 某些路由器/运营商/安全 DNS 会过滤“公网域名返回私有地址”的响应，直接解析失败。

这不是换卡造成的，是 DuckDNS + 私有 LAN 的固有行为。

### 3.2 换卡没有改 DuckDNS 配置

克隆会把整个根文件系统复制到新卡，包括：

- `/etc/config/dashplay`（UCI 里的 `duckdns_domain` / `duckdns_token`）；
- `/opt/dashplay/state/own-domain.json`（记录状态）；
- `/opt/dashplay/state/tls/own/`（Let's Encrypt 证书）；
- `/etc/config/dhcp`（dnsmasq 的 `rebind_domain`）；
- receiver 和 DashPlay 程序本身。

DuckDNS 记录是外部服务上的数据，不在卡里；F50 启动后 `own_domain.Maintainer` 会重新发布记录。日志里的 `OK` 证明它已经发布成功。

### 3.3 最可能的客户端原因

按可能性排序：

1. **测试设备不在 `DVA` 上**：最常见。用手机流量或家里 WiFi 打开 `hika-tesla.duckdns.org`，解析到 `100.96.0.1` 也连不上。
2. **客户端 DNS 不是 F50**：手机/电脑用了 8.8.8.8、DoH、广告拦截 DNS、iCloud Private Relay、VPN 等，可能过滤私有地址或返回旧记录。
3. **DNS 缓存**：特斯拉或手机缓存了换卡前的旧地址；DuckDNS TTL 只有 60 秒，但客户端可能缓存更久。
4. **代理**：Mac/Windows 上的本地代理（本次 Mac 的 `remote_ip=127.0.0.1` 就是代理）可能把域名请求转到别处。
5. **特斯拉车机的 DNS/缓存**：车机没走 F50 的 DHCP DNS，或车机自己缓存了旧记录；重启车机浏览器/等待 TTL 后再试。
6. **证书/端口**：本次证书有效，receiver 在跑；如果客户端仍报证书错误，先确认它访问的是 `https://...:18443/`，且车机时间正确。

---

## 4. 正确的访问方式

在 F50 特斯拉模式下，车机/手机应该：

1. 连接 F50 的 WiFi `DVA`；
2. 使用 DHCP 自动获取地址和 DNS（不要手动设 8.8.8.8）；
3. 关闭 VPN、代理、iCloud Private Relay、广告拦截 DNS；
4. 打开：

```text
https://hika-tesla.duckdns.org:18443/
```

注意：

- 必须是 **https**；
- 端口是 **18443**；
- 不要用 `http://` 或 80 端口；
- 不要在车外/手机流量下测试这个域名——它不是公网入口。

## 5. 继续排查的步骤

### 5.1 先确认客户端在 `DVA` 上

在客户端（手机/电脑）上查：

```text
nslookup hika-tesla.duckdns.org
```

应该返回：

```text
Address: 100.96.0.1
```

如果返回别的地址、超时或 NXDOMAIN：

- 客户端不在 F50 的 DHCP/DNS 下，或用了别的 DNS；
- 关闭代理/VPN/Private Relay；
- 把 DNS 改成自动（DHCP）或手动设为 `100.96.0.1`；
- 等 60 秒或切换一次 WiFi，清掉缓存。

### 5.2 直接测 F50 的 HTTPS

在客户端上：

```bash
curl -k -sS -o /dev/null -w '%{http_code}\n' https://100.96.0.1:18443/
```

- 返回 `200`：F50 的页面可达，问题在域名/DNS；
- 连不上：客户端不在 `DVA`，或 F50 的 receiver/防火墙有问题。

### 5.3 在 F50 上复核

SSH 登录 F50（特斯拉模式地址 `100.96.0.1`），执行：

```sh
cat /opt/dashplay/state/own-domain.json
nslookup hika-tesla.duckdns.org 127.0.0.1
grep -i duckdns /var/run/dashplay/supervisor.log | tail -5
/etc/init.d/dashplay status
openssl x509 -in /opt/dashplay/state/tls/own/fullchain.pem -noout -subject -issuer -dates
```

期望：

- `record: ok`、`address: 100.96.0.1`、`phase: ready`；
- 本机解析到 `100.96.0.1`；
- 日志最后是 `OK`；
- `dashplay` running；
- 证书 `CN=hika-tesla.duckdns.org`，未过期。

如果 `record` 是 `failed` 或 `blocked`：

- `failed`：F50 当时没网或 DuckDNS 暂时失败；等 60 秒会自动重试，或重启 `dashplay` 触发；
- `blocked`：特斯拉无法打开当前地址，程序故意保留旧记录；检查 F50 的 LAN 地址和特斯拉模式。

### 5.4 特斯拉专用检查

- 车机 WiFi 必须是 `DVA`；
- WiFi 的 IP/DNS 设为自动（DHCP）；
- 关闭车机上的 VPN/代理（如果有）；
- 重启车机浏览器/娱乐系统，或等待 1–2 分钟让 DNS 缓存过期；
- 打开 `https://hika-tesla.duckdns.org:18443/`，不是 `http://`；
- 如果车机报证书错误：确认车机系统时间正确，证书是 Let's Encrypt 正式证书（本次有效到 2027-02-02）。

### 5.5 用手机做对照

用一台手机连 `DVA`，关闭代理/VPN，打开同一个 URL：

- 手机能开、车机不能开：问题在车机的 DNS/缓存/浏览器；
- 手机也不能开：问题在 F50 或客户端网络；
- 手机解析不到 `100.96.0.1`：DNS/代理问题。

---

## 6. 如果确实需要从车外访问

当前设计**不支持**从车外通过 `hika-tesla.duckdns.org` 访问：

- 域名指向 `100.96.0.1`，这是 F50 的私有 LAN 地址；
- DuckDNS 只是 DNS，不是隧道；
- F50 的 SIM 可能还在 CGNAT 后面，改成公网 IP 也不一定可达；
- 从车外访问需要额外的 VPN（WireGuard/Tailscale 等）或反向隧道，属于另一套方案，不是当前 DashPlay 的默认用法。

不要为了“从外面能打开”把 DuckDNS 记录改成 SIM 的公网 IP：这会破坏车机在 F50 WiFi 内的访问，而且 CGNAT 下通常也打不开。

## 7. 本次排查后的环境变化

排查结束后再次尝试 SSH 时：

- `100.96.0.1` ping 超时（F50 可能已断电、拔线或换到别的网络）；
- Mac 上的原 WORK 目录 `/Users/hikari/dashplay-install.hhumnk` 已不存在（可能已复制到 Windows 或被清理）。

这不影响上面的结论，但下次继续排查前需要：

1. F50 上电，电脑连 `DVA` 或通过 USB 网络访问 `100.96.0.1`；
2. 准备 SSH 私钥或 root 密码：
   - 如果 WORK 里的 `f50/private/ssh-key` 和 `openwrt-root-password.txt` 已复制到 Windows，用它们；
   - 如果都没有，按换卡方案 5.4 在克隆卡上追加一把新 key（需要重新挂载卡），或用记得的 root 密码；
3. 再执行第 5.3 节的命令。

## 8. 一句话总结

**换卡没有弄丢 DuckDNS：F50 上的域名、token、记录、证书、receiver 都正常，记录已指向 `100.96.0.1`。** 这个域名只对连在 F50 WiFi `DVA` 上的设备有效；如果客户端不在 `DVA`、用了别的 DNS/代理/VPN，或缓存了旧记录，就会“访问不了”。先确认客户端在 `DVA`、DNS 返回 `100.96.0.1`、关闭代理，再用 `https://hika-tesla.duckdns.org:18443/` 测试。
