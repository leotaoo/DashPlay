## 4. 安装时间线

1. **F0**：`F50_OK check`，独立 Python 3.12、固定工具和 venv 依赖就绪。
2. **F1 备份**：`BACKUP_VERIFIED 69 of 75`，约 3.3 GiB，备份在 `$WORK/f50/backup`，只留在本机。
3. **F1 Root**：写 `boot_b`、`trustos_b`，`READBACK_OK before/boot/trustos` 全部通过；重启后 Magisk 运行、`su` 返回 `uid=0`、`sys.boot_completed=1`、固件 B16。
4. **F1 差异**：`ro.boot.slot_suffix=_a`，脚本期望 `_b`；`boot_a`、`boot_b` 都已是 Root 镜像；脚本因 ADB 连接超时停在 `F50_STOP flash`，人工核对后继续并标记 F1。
5. **F2 第一次 dry-run**：安装器计划 Linux 写 `boot_b`、Android A 保留、SD 写 `mmcblk1p1`；包装脚本期望 Android B / Linux A、整卡 `mmcblk1`，判定不符合，`F50_STOP openwrt`。
6. **槽位修复尝试**：写 `slot-b-trial` 到 misc 0x800，清空 SD 分区表，重启；设备仍从 A 启动，misc 被改写回 A 正常块。
7. **Plan B**：按安装器原生布局 Android A / Linux B 安装 OpenWrt；SD 卡改为整卡 `mmcblk1`；OpenWrt 25.12.5 从 Linux B 槽启动。
8. **F3**：第一次 GitHub API 403 限流；恢复后 `urllib` 被代理 SSL EOF 打断；改用 `curl` 下载官方 5 个 `aarch64_generic` 资产 + `SHA256SUMS` 校验 + 本地 release feed；OpenWrt 源切清华镜像；最终 63 秒安装成功。
9. **F4**：`F50_OK identity`，DiPlay v0.2.22，`IDENTITY_MATCH`。
10. **特斯拉模式**：`F50_OK tesla`；LAN `100.96.0.1/24`，接收端 `--tesla`，`"tesla": true`；WiFi 首次 TR/36，按已知兼容性改 CN/149。
11. **iPhone 配对**：在 iPhone 蓝牙里配对盒子；iPad 只当设置页。
12. **管理方式**：F50 从 Mac 拔掉，由 iPad 通过 `DVA` 管理；Mac 需要时连 DVA 或再插 USB。

### 5.1 启动槽 A/B 不匹配（F1/F2）

**现象**：F1 脚本期望设备从 B 槽启动，实际 `ro.boot.slot_suffix=_a`；F2 dry-run 输出安装器计划 Linux 写 `boot_b`、Android A 保留、SD 写 `mmcblk1p1`，而包装脚本期望 Android B / Linux A、整卡 `mmcblk1`，因此拒绝。

**原因**：

- 这台 F50 实际从 Android A 槽启动；B 槽在 misc 启动控制块里 `tries=0`，不是可启动的 Android 槽。
- F1 只写 `boot_b`、`trustos_b`，不修改 misc 的 AOSP bootloader_control 块；启动器仍选 A。
- F2 包装脚本假设太窄，只接受 Android B / Linux A 和整卡；mu300 安装器本身会按实际槽位自适应。

**解决**：

- 不强行切 B 槽；保留 Android A，按安装器原生布局 **Android A / Linux B** 安装。
- 清空 SD 卡分区表，改为整卡 `mmcblk1`。
- 手动核对 `boot_a` 未变、安装日志无错误、OpenWrt 从 B 槽启动、`192.168.77.1`、SSH、`mu300-next-boot linux`、防火墙。

**结果**：OpenWrt 25.12.5 从 Linux B 槽运行，默认启动 Linux，连续 5 次失败回 Android A。

### 5.2 F1 ADB 连接超时

**现象**：F1 最后一步 `adb connect 192.168.0.1:5555` 超时，脚本以 `F50_STOP flash` 结束，未执行 `_b` 槽位断言。

**原因**：ADB 连接超时掩盖了后续检查；不是 Root 写入失败。

**解决**：人工通过 ADB 验证 Magisk 守护进程、`uid=0`、`sys.boot_completed=1`、B16；记录 `_a` 差异；经用户同意后人工标记 F1 完成。

### 5.3 F2 dry-run 被拒

**现象**：`F50_STOP openwrt: installer would not use the SD card`，没有任何写入。

**原因**：包装脚本与安装器的槽位/整卡假设不一致（见 5.1）。

**解决**：走 Plan B；清空 SD 分区表；直接使用安装器的实际布局。安装器本身支持该布局，且有 5 次启动回退。

### 5.4 B 槽不可启动 Android

**现象**：写 `slot-b-trial` 块到 misc 0x800 后重启，设备仍回到 A，misc 被改写为 A 槽正常块。

**原因**：B 槽在这台设备上不是可启动 Android 槽，而是备用/其他系统槽。

**解决**：不再强切；使用 Android A / Linux B。

### 5.5 GitHub API 限流 + 代理 SSL EOF

**现象**：

- F3 第一次运行失败：`F50_STOP dashplay: URLError: <urlopen error [SSL: UNEXPECTED_EOF_WHILE_READING] ...>`。
- 检查发现 GitHub API 未认证限流：HTTP 403，`x-ratelimit-limit: 60`，`x-ratelimit-remaining: 0`，重置时间 2026-11-04 21:34:04 CST。
- 额度恢复后，Python `urllib` 仍被代理以 SSL EOF 打断。

**解决**：

1. 等额度重置后重跑；或从官方 release 页面手动下载 F50 对应的 5 个 `aarch64_generic` 资产，用 `SHA256SUMS` 核对。
2. 改用 `curl` 下载官方 5 个资产（`dashplay`、JRE、LuCI app、中文语言包、`SHA256SUMS`），全部校验通过。
3. 生成本地 release feed（`file://`），把临时副本的 `FEED` 指向本地；只改下载源，不改设备检查、dry-run、读回或 SHA256 校验。
4. 重跑 F3，脚本发现本地文件已存在，跳过下载，仍执行校验、推送、`apk add` 和蓝牙检查。

**结果**：`F50_OK dashplay`，DashPlay 2026.11.02-r1 运行。

### 5.6 OpenWrt 源慢

**现象**：F3 的 `apk add` 依赖下载约 8–40 KB/s，超过 5 分钟未完成。

**对比**：国内阿里云大文件约 396 KB/s；`downloads.openwrt.org` 约 40 KB/s；ping 158–260 ms，DNS 优先返回 Fastly IPv6。

**解决**：

- 备份 F50 的 `/etc/apk/repositories.d/distfeeds.list` 为 `distfeeds.list.bak`。
- 把 `https://downloads.openwrt.org` 替换为 `https://mirrors.tuna.tsinghua.edu.cn/openwrt`。
- `apk update` 成功：`OK: 11183 distinct packages available`。
- 保留清华源；原源备份在设备上，需要时可恢复。
- 注意：清华和中科大都有 25.12.5；阿里云只有 25.12.0，不能用；8 个 feed 路径已逐个验证。

**结果**：依赖下载明显加速，F3 最终安装 63 秒。

### 5.7 特斯拉 WiFi 信道/国家

**原因/已知记录**：特斯拉实车记录里信道 36 可能搜不到；已验证设置是 CN / 149。

**解决**：用户确认在中国境内并同意后，重跑：

```sh
"$PY" "$DP/scripts/f50-install.py" tesla "$WORK" --sim yes --cn-149
```

**结果**：`F50_OK tesla`；`wireless.radio0.country='CN'`、`channel='149'`；`iwinfo` 显示 `Channel: 149 (5.745 GHz)`，SSID `DVA`；设置页和 CarPlay 页仍返回 200。`iwinfo` 仍报告 Tx-Power 0 dBm，待实车确认；若特斯拉搜不到或信号差，再查 WiFi 驱动/功率。

### 5.8 iPhone 配对

**现象**：在 iPad 上点「添加 iPhone」后没有反应，用户不确定要配哪个蓝牙。

**原因**：iPad 只是打开设置页的“另一台设备”，要配对的是 **iPhone**；iPad 的蓝牙列表不参与。

**解决**：

- iPhone 打开「设置 → 蓝牙」，停在页面；
- 在「其他设备」里选择新出现的盒子蓝牙设备；
- 核对六位数字并在两边确认；
- 配对成功后 iPhone 会出现在 DashPlay 设置页；
- 「添加 iPhone」后 iPad 不一定弹窗，配对窗口在等 iPhone，以 iPhone 的蓝牙列表为准。

### 5.9 Mac USB 断开

**现象**：拔掉 F50 后 Mac 无法 SSH/路由，无法继续管理。

**解决**：用 iPad 通过 `DVA` WiFi 管理；Mac 需要时连 `DVA` 或再插 USB。

### 5.10 512GB → 256GB 换卡

**现象**：原卡 512GB，目标卡 256GB；直接 `dd` 会写不下或截断。

**解决**：

- Linux/WSL2 里只读挂载原卡；
- `tar` 打包到 Windows 磁盘；
- 256GB 卡上重建同 label（`mu300sd`）、同 UUID、同 ext4 特性的文件系统；
- 解包；
- 逐文件 `MANIFEST_OK` / `SHA256_OK` 校验；
- 插回 F50 冷启动验收。

**关键点**：

- 原卡全程只读；验收前不要格式化/覆盖；
- 目标卡必须整卡 ext4（不是 `p1`），label `mu300sd`；
- 目标卡特性必须与源卡一致，尤其不能多出 `orphan_file`；
- 换卡方案详见 `F50-SD卡复制到256G-Windows方案-2026-11-04.md`。

**结果**：256GB 卡可启动，大部分功能正常；DuckDNS 访问问题见 5.14。

### 5.11 `orphan_file` 特性不兼容

**现象**：新版 Ubuntu 的 `mkfs.ext4` 默认开启 `orphan_file`，而 F50 的 5.4 内核不支持；如果目标卡带这个特性，F50 无法挂载新卡。

**原因**：源卡由 `mke2fs 1.46.2` 创建，没有 `orphan_file`；新版 e2fsprogs（1.47+）默认会加。

**解决**：

- 用 `dumpe2fs -h` 读取源卡 `Filesystem features`；
- 目标卡用 `-O none,<源特性>` 重建，或至少 `-O ^orphan_file`；
- 用 `diff` 核对目标卡特性与源卡完全一致；
- 目标卡多出 `orphan_file` 时绝不能插回 F50。

**结果**：目标卡特性与源卡一致，可启动。

### 5.12 原卡 `Filesystem state` 不是 `clean`

**现象**：原卡文件系统状态不是 `clean`（可能因为之前直接拔电/强制关机）；此时克隆可能拿到不一致的数据。

**解决**：

1. 原卡插回 F50，上电进 OpenWrt；
2. SSH 登录后执行：

```sh
sync
poweroff
```

3. 等 SSH 断开、WiFi `DVA` 消失、指示灯灭；再等 10–20 秒取卡；
4. 不要直接拔电，不要长按电源键强制关机；
5. 如果 `poweroff` 不可用，用 `halt`；不要用 `reboot`（会重新挂载 SD 卡）；
6. 没有 SSH 时，用 LuCI：`http://100.96.0.1/`（特斯拉模式）或 `http://192.168.77.1/`，root 登录，System → Reboot → Power Off。

### 5.13 WORK 里的 key/password

**用途**：验收时 SSH 进 F50 核对 `df -h /`、`blkid`、`/proc/partitions`、`mu300-next-boot status`、DashPlay 日志。不是启动必需。

**文件**：

- `f50/private/ssh-key`：原安装生成的 Ed25519 私钥；公钥已写入 F50 的 `/etc/dropbear/authorized_keys`，克隆会复制公钥和 `/etc/shadow`，所以原私钥/密码仍然有效。
- `f50/private/openwrt-root-password.txt`：root 密码；本机这份文件里就是密码本身（12 字符，可能带换行），不是 `user: root` 格式；可直接用于 SSH/LuCI。

**当前情况（2026-11-04 排查时）**：Mac 上的 `/Users/hikari/dashplay-install.hhumnk` 已不存在（可能已复制到 Windows 或清理）。

**如果没有 key/password**：

### 5.14 DuckDNS 域名访问不了

**现象**：换卡后 `hika-tesla.duckdns.org` 打不开。

**F50 侧实测**：

```json
{
  "name": "hika-tesla.duckdns.org",
  "record": "ok",
  "address": "100.96.0.1",
  "ipv6": "",
  "ipv6_state": "off",
  "phase": "ready",
  "reason": ""
}
```

- F50 能上网（`ping 1.1.1.1` 通）；
- dnsmasq running，`rebind_domain='/hika-tesla.duckdns.org/'`；
- 本机解析 `hika-tesla.duckdns.org` → `100.96.0.1`；
- 证书 Let's Encrypt，CN=`hika-tesla.duckdns.org`，有效期至 2027-02-02；
- receiver running；
- supervisor 日志：`duckdns ... failed` 后 `OK`（首次是上行未就绪，重试成功）。

**结论**：克隆没有弄丢 DuckDNS 配置。域名指向 `100.96.0.1`，这是 F50 的私有 LAN 地址，**只对连在 F50 的 WiFi `DVA` 上的设备有效**；从家里/公司/手机流量访问，解析到 `100.96.0.1` 也到不了。这不是换卡造成的。

**更可能的客户端原因**：

1. 测试设备不在 `DVA`；
2. 客户端用了别的 DNS / DoH / 代理 / VPN / Private Relay；
3. 特斯拉或手机缓存了旧 DNS；
4. 客户端把 `100.96.0.1` 当私有地址过滤（rebind protection）；
5. 代理（本次 Mac 的 `curl` 显示 `remote_ip=127.0.0.1`，说明走了本地代理）。

**排查**：

- 手机连 `DVA`、关代理/VPN，`nslookup hika-tesla.duckdns.org` 应为 `100.96.0.1`；
- 打开 `https://hika-tesla.duckdns.org:18443/`（必须 https、18443）；
- 特斯拉 WiFi 设为自动 DHCP，重启车机浏览器/等待缓存过期；
- 详见 `F50-换卡后DuckDNS访问排查-2026-11-04.md`。

## 7. 建议与后续

### 7.1 安装脚本/流程改进

1. **F0/F1 预检**：读取 `ro.boot.slot_suffix` 和 misc 0x800 块；如果是 Android A，先决定走安装器的 A/B 布局还是停止。
2. **F1 结束断言**：把 `_b`、B16、root、`boot_completed` 作为硬性条件；`_a` 时明确停下。
3. **F2 包装脚本**：接受安装器实际 `slot_setup` 的 A/B 或 B/A 两种布局；不要把整卡/分区写死。
4. **SD 卡模式**：把 `sd_probe` 的“有分区用 p1、无分区用整卡”两种结果都记录到检查里。
5. **设备历史**：安装前检查 `/data/adb/magisk` 等 Root 痕迹；同型号同版本不足以判断启动状态。
6. **下载源**：支持 `GITHUB_TOKEN` 或本地镜像/预下载目录，避免共享出口 IP 的 60 次/小时限制；代理环境下优先 `curl`。

### 7.2 换卡后续

- 原 512GB 卡保留至少一周；确认 256GB 卡冷启动、CarPlay、配对、特斯拉模式都正常后再考虑复用。
- 不要在克隆好的卡上再跑 `f50-install.py openwrt`（会清空 SD 卡）。
- 如果目标卡特性多出 `orphan_file`，不要插回 F50；重做文件系统。
- 如果原 WORK 的 key/password 没有另存，按换卡方案 5.4 追加新 key，或用记得的 root 密码。

### 7.3 DuckDNS 后续

- 先在手机连 `DVA`、关代理，确认 `nslookup` 返回 `100.96.0.1`；
- 再用 `https://hika-tesla.duckdns.org:18443/` 测试；
- 特斯拉仍不行时，重点查车机 DNS/缓存和是否走 F50 的 DHCP DNS；
- 不要为了“从车外访问”把 DuckDNS 记录改成 SIM 公网 IP；当前设计是私有地址 + 车机本地访问。
