# F50 SD 卡迁移方案：512GB 原卡 → 256GB 新卡（Windows 执行版）

- 日期：2026-11-04
- 适用：ZTE F50，OpenWrt + DashPlay 从 SD 整卡启动
- 目标：把现在能正常启动的 512GB 原卡复制到 256GB 新卡，保留 DashPlay 认证、iPhone 配对、WiFi 与特斯拉设置
- 执行机：Windows 10/11 + WSL2 Ubuntu + usbipd-win
- 预计耗时：30–60 分钟（取决于读卡器速度）

---

## 0. 先看结论

- **不能 `dd` 整卡复制**：原卡 512GB，目标卡 256GB，写不下，会中途失败或截断。也不要用 balenaEtcher/Rufus 把原卡做成 512GB 镜像再写到 256GB 卡——同样写不下。
- 原卡是**整卡 ext4、没有分区表**，label 为 `mu300sd`；F50 安装器用 `mke2fs 1.46.2` 创建，inode 比例为 1 MiB/个。
- F50 的内核与启动分区在 eMMC 的 `boot_a`，**根文件系统在 SD 卡上**；同一张卡插在同一个卡槽，设备名仍是 `/dev/mmcblk1`。
- 做法：Linux 里**只读**挂载原卡 → `tar` 打包到 Windows 磁盘 → 在 256GB 卡上重建**同 label、同 UUID、同特性**的 ext4 → 解包 → 逐文件 SHA-256 校验 → 插回 F50 冷启动验收。
- **原卡全程只读**；新卡验收通过前，不要格式化、不要覆盖、不要拿原卡做实验。

### 流程总览

1. Windows 装 WSL2 + usbipd-win；
2. 原卡接入 WSL → 只读检查 → 挂载 → `tar` 打包 + 生成清单/哈希；
3. 换 256GB 卡 → 建同 label/UUID/特性的 ext4 → 解包 → 对比清单和 SHA-256；
4. 新卡插回 F50 → 冷启动 → 验收 CarPlay、配对、特斯拉模式；
5. 原卡保留至少一周，确认无误后再考虑复用。

### 为什么不能直接用 Windows 资源管理器复制

- Windows 原生读不了 ext4，插入后会提示“需要格式化”——**点取消**，也不要在磁盘管理里初始化。
- 普通文件复制会丢权限、属主、xattr、设备节点；必须用 `tar` 或 `rsync`。
- 只改 label 不保留 UUID 有风险：启动参数可能按 UUID 找根文件系统；保留最稳。

### 关键事实（来自本次安装日志）

```text
creating ext4 mu300sd on /dev/block/mmcblk1 (one inode per 1024 KiB)
mke2fs 1.46.2 (28-Feb-2021)
```

这说明：

1. 文件系统直接建在**整张卡**上（不是 `mmcblk1p1`）；
2. label 是 `mu300sd`；
3. 源文件系统由较老的 e2fsprogs 1.46.2 创建，**没有 `orphan_file` 特性**。新版 Ubuntu 的 `mkfs.ext4` 默认会开启 `orphan_file`，而 F50 的 5.4 内核不支持它——这会导致新卡无法挂载。下面的步骤会强制复制源卡的特性集合并做检查。

## 1. 准备清单

- [ ] 512GB 原卡（当前能正常启动的那张）
- [ ] 256GB 目标卡（会被完全清空；卡上原有数据已自行备份）
- [ ] USB 3.0 读卡器；优先直插机箱后置 USB 口，不要用 Hub
- [ ] microSD 转接套（如果是 microSD；用可靠的原厂套，避免接触不良）
- [ ] 转接套/读卡器的写保护开关已关闭（目标卡要写；源卡只读不受影响）
- [ ] Windows 10/11，管理员权限，能上网（装 WSL/usbipd-win、apt 下载）
- [ ] 本文件已复制到 Windows
- [ ] （可选，建议）原安装 WORK 目录里的 `f50/private/ssh-key` 和 `f50/private/openwrt-root-password.txt`（用于启动后 SSH 核对；没有也能靠 WiFi/CarPlay 验收；在 Mac 上，形如 `/Users/hikari/dashplay-install.xxxxxx/f50/private/`）

### 这两个文件是做什么的（不是启动必需）

- `f50/private/ssh-key`：原安装 `f50-install.py` 生成的 Ed25519 **私钥**；它的公钥当时写进了 F50 的 `/etc/dropbear/authorized_keys`。克隆会把这份**公钥**和 `/etc/shadow` 一起复制到新卡，所以原私钥仍然能登录克隆后的 F50。它是验收时最方便的登录方式。
- `f50/private/openwrt-root-password.txt`：安装器生成的 root 密码。本机这份文件里就是密码本身（可能带一个换行），不是 `user: root` 那种格式；SSH/LuCI 登录时直接输入。克隆后的 `/etc/shadow` 里是同一个密码哈希，所以密码仍然有效；如果私钥丢了，或者 Windows 上的 SSH 不接受这个 key，可以用密码登录（OpenWrt 的 Dropbear 默认允许密码），也可以登录 LuCI。
- **没有它们也能启动**：F50 启动、WiFi、CarPlay、iPhone 配对都不依赖这两个文件；它们只用于启动后的 SSH 核对（`df -h /`、`blkid`、`/proc/partitions`、`mu300-next-boot status`、DashPlay 日志）。没有就按第 6 节的可视验收做，或者在 5.4 里给新卡加一把新钥匙（要在卸载之前）。
- **私钥不在卡上**：卡里只有公钥；私钥只在原 WORK（或你复制的位置）。密码明文也只在原 WORK；卡里只有哈希。所以原 WORK 丢了，不能从卡里“导出”私钥或明文密码。

> **2026-11-04 备注**：排查 DuckDNS 时，Mac 上的 `/Users/hikari/dashplay-install.hhumnk` 已经不存在（可能已复制到 Windows 或清理）。如果私钥/密码没有另存，按 5.4 给新卡追加新 key，或用记得的 root 密码。

## 2. 安装 WSL2 和 usbipd-win

以下命令在**管理员 PowerShell**里执行。

### 2.1 安装或更新 WSL2

```powershell
wsl --install -d Ubuntu
wsl --set-default-version 2
wsl -l -v
```

- `wsl -l -v` 的 `VERSION` 必须是 **2**；不是 2 就先 `wsl --set-version Ubuntu 2`。
- 如果提示重启，重启后再继续。
- 首次进入 Ubuntu 时按提示设置 Linux 用户名和密码。

### 2.2 安装 usbipd-win

```powershell
winget install --interactive --exact dorssel.usbipd-win
usbipd --version
```

如果 `winget` 失败，打开 <https://github.com/dorssel/usbipd-win/releases> 下载最新 `.msi` 安装。这是第三方开源工具，不是微软官方组件。

### 2.3 防止电脑睡眠（可选，建议）

```powershell
powercfg /change standby-timeout-ac 0
```

### 2.4 在 WSL 里安装工具

打开 Ubuntu 终端：

```bash
sudo apt update
sudo apt install -y e2fsprogs
```

`tar`、`find`、`sha256sum`、`lsblk`、`blkid` 都是基础包，通常已自带。

## 3. 源卡：只读挂载并打包

### 3.1 把源卡接到 WSL

插入**512GB 原卡**，管理员 PowerShell：

```powershell
usbipd list
```

找到读卡器对应的 BUSID，例如：

```text
BUSID  VID:PID    DEVICE                    STATE
2-1    05e3:0610  USB Mass Storage Device    Not shared
```

绑定并接入 WSL：

```powershell
usbipd bind --busid 2-1
usbipd attach --wsl --busid 2-1
```

`attach` 到 WSL 后，所有 WSL2 发行版都能看到这张卡，不需要指定发行版。执行 attach 后请**保持一个 WSL 终端打开**：WSL2 轻量虚拟机被关掉时，设备会断开。

在 WSL 里确认（以下 WSL 命令都在 Ubuntu 的 bash 里执行；`/mnt/c` 默认就是 Windows 的 C: 盘）：

```bash
lsblk -o NAME,SIZE,MODEL,SERIAL,TRAN,LABEL,FSTYPE
```

**如果看不到卡：**

```bash
sudo dmesg | tail -30
```

- 确认 `wsl -l -v` 是 VERSION 2；
- 拔插读卡器；
- 换一个 USB 口（不要 Hub）；
- 换一个读卡器；
- `usbipd detach --busid 2-1` 后重新 attach。

### 3.2 确认源卡布局

```bash
SRC=/dev/sdb   # ← 按 lsblk 改成 512G 那个，不要照抄
lsblk -o NAME,SIZE,LABEL,FSTYPE "$SRC"
sudo blkid "$SRC"
sudo blockdev --getsize64 "$SRC"

# 容量护栏：源卡应在 450–550 GB 之间
[ "$(sudo blockdev --getsize64 "$SRC")" -gt $((450*1000*1000*1000)) ] && \
[ "$(sudo blockdev --getsize64 "$SRC")" -lt $((550*1000*1000*1000)) ] && echo SOURCE_SIZE_OK
```

必须看到 `SOURCE_SIZE_OK`；没有就停止，说明 `SRC` 不是那张 512GB 卡。

期望输出类似：

```text
NAME   SIZE LABEL    FSTYPE
sdb  476.9G mu300sd  ext4
```

**重要检查：**

- 必须是**整卡 ext4**，也就是 `sdb` 本身有 `FSTYPE=ext4`；
- 如果显示 `sdb` 下面还有 `└─sdb1`，说明卡是分区的，**停止**，把 `lsblk -f` 输出发回，不要按本方案继续；
- 源卡不能有挂载点；如果 `lsblk` 显示已挂载，先 `sudo umount <挂载点>`；
- 容量约 476.9 GiB（512GB 十进制）是正常的，不要被数字差异吓到。

### 3.3 记录源卡信息

```bash
mkdir -p /mnt/c/f50-sd
{
  echo "===== source ====="
  sudo blkid "$SRC"
  echo "bytes=$(sudo blockdev --getsize64 "$SRC")"
  sudo dumpe2fs -h "$SRC" 2>/dev/null | grep -E \
    'Filesystem volume name|Filesystem UUID|Filesystem features|Filesystem state|Block count|Block size|Inode count|Inode size|Reserved block count|Free blocks|Free inodes'
} | tee /mnt/c/f50-sd/source-info.txt
```

把 `Filesystem UUID` 和 `Filesystem features` 抄到上面的记录表里。

**检查 `Filesystem state`：必须是 `clean`。** 如果显示 `not clean`，不要继续——把原卡插回 F50，正常关机后再取卡，重新从 3.3 开始。不要对源卡执行修复。

**怎么在 F50 上正常关机：**

1. 原卡插回 F50，上电，等它进入 OpenWrt（WiFi `DVA` 出现，约 40–60 秒）。
2. 电脑连 `DVA`，SSH 登录：

   ```bash
   ssh -i <原 WORK>/f50/private/ssh-key root@100.96.0.1
   # 如果还没开特斯拉模式，地址是 192.168.77.1
   ```

   没有私钥就用 root 密码登录（`openwrt-root-password.txt`）。

3. 执行：

   ```sh
   sync
   poweroff
   ```

4. 等待 SSH 断开、WiFi `DVA` 消失、F50 指示灯灭；再等 10–20 秒，取出 SD 卡。

   - **不要直接拔电，也不要长按电源键强制关机。**
   - 如果 `poweroff` 后 WiFi 消失但指示灯还亮，说明机器已停机但没切断电源；等 SSH 断开、WiFi 消失后再取卡。
   - 如果 `poweroff` 命令不存在，用 `halt`；**不要用 `reboot`**（它会重新挂载 SD 卡）。

**没有 SSH 的话，用 LuCI：** 浏览器打开 `http://100.96.0.1/`（特斯拉模式）或 `http://192.168.77.1/`，用 root 密码登录，进 **System → Reboot → Power Off**。如果页面只有 Reboot 没有 Power Off，不要点 Reboot，改用 SSH。

### 3.4 只读检查并挂载

先做一次**只读**文件系统检查（`-n` 表示不写任何东西）：

```bash
sudo e2fsck -fn "$SRC"
```

输出应为 `clean`；如果报告错误或 `Filesystem wasn't cleanly unmounted`，停止，不要加 `-y`。

然后挂载：

```bash
sudo mkdir -p /mnt/orig
sudo mount -o ro,noload "$SRC" /mnt/orig
findmnt /mnt/orig
sudo du -sx --block-size=1 /mnt/orig
sudo find /mnt/orig -xdev | wc -l
```

- `ro`：只读；
- `noload`：不重放 journal，避免任何写入。

**如果挂载失败：**

- `wrong fs type`：源卡不是 ext4，或读卡器没接好，停止；
- `recovery required` / 提到 journal：**不要对源卡跑 `e2fsck -y`**，停止并把报错发回；
- 其他报错也先停止，不要猜。

### 3.5 生成源卡清单和哈希

```bash
cd /mnt/orig
sudo find . -xdev -printf '%P\t%y\t%m\t%U\t%G\t%l\n' \
  | LC_ALL=C sort > /mnt/c/f50-sd/source-manifest.txt
sudo find . -xdev -type f -print0 \
  | LC_ALL=C sort -z \
  | sudo xargs -0 sha256sum > /mnt/c/f50-sd/source-sha256.txt
wc -l /mnt/c/f50-sd/source-manifest.txt /mnt/c/f50-sd/source-sha256.txt
```

### 3.6 打包

```bash
sudo tar -cpf /mnt/c/f50-sd/rootfs.tar \
  --numeric-owner --xattrs --xattrs-include='*' --acls --sparse --one-file-system .
ls -lh /mnt/c/f50-sd/rootfs.tar
tar -tf /mnt/c/f50-sd/rootfs.tar | wc -l
```

- `--numeric-owner`：保留数字 UID/GID；
- `--xattrs --xattrs-include='*'`：保留扩展属性（包括 capability）；
- `--acls`：保留 ACL；
- `--sparse`：保留稀疏文件；
- `--one-file-system`：不跨文件系统。

如果 `tar` 报 `file changed as we read it`，停止——源卡不应在变化。

### 3.7 卸载源卡

```bash
cd /
sudo umount /mnt/orig
```

PowerShell：

```powershell
usbipd detach --busid 2-1
```

然后在 Windows 里“安全删除硬件”，拔出源卡，贴上标签：

> **原卡 512GB — 唯一能启动的系统，验收前不要动**

## 4. 目标卡：重建文件系统

### 4.1 接入目标卡

插入**256GB 目标卡**，管理员 PowerShell：

```powershell
usbipd list
usbipd bind --busid <目标 BUSID>       # 如果提示 already bound，直接跳过
usbipd attach --wsl --busid <目标 BUSID>
```

WSL：

```bash
lsblk -o NAME,SIZE,MODEL,SERIAL,TRAN,LABEL,FSTYPE
sudo blkid
```

设目标卡变量：

```bash
TGT=/dev/sdc   # ← 按 lsblk 改成 256G 那个，不要沿用源卡的 /dev/sdb
sudo blockdev --getsize64 "$TGT"

# 容量护栏：目标卡应在 200–300 GB 之间
[ "$(sudo blockdev --getsize64 "$TGT")" -gt $((200*1000*1000*1000)) ] && \
[ "$(sudo blockdev --getsize64 "$TGT")" -lt $((300*1000*1000*1000)) ] && echo TARGET_SIZE_OK
```

必须看到 `TARGET_SIZE_OK`；没有就停止，说明 `TGT` 不是那张 256GB 卡（或者你选到了 WSL 自己的虚拟磁盘）。

**确认：**

- 容量约 238.5 GiB（256GB 十进制）；
- 没有 `mu300sd` 标签；
- 当前只有这一张目标卡接在 WSL 里；
- 目标卡没有挂载点；如果 `lsblk` 显示已挂载，先 `sudo umount <挂载点>`；
- 不要相信“和刚才一样是 `/dev/sdb`”，换卡后设备名可能变。

### 4.2 读取源卡记录

```bash
SRC_UUID=$(awk -F': *' '/Filesystem UUID/{print $2}' /mnt/c/f50-sd/source-info.txt | tr -d '[:space:]')
SRC_FEATURES=$(awk -F': *' '/Filesystem features/{print $2}' /mnt/c/f50-sd/source-info.txt | sed 's/^[[:space:]]*//; s/[[:space:]]*$//')
SRC_BS=$(awk -F': *' '/Block size/{print $2}' /mnt/c/f50-sd/source-info.txt | tr -d '[:space:]')
FEATURE_LIST=$(echo "$SRC_FEATURES" | tr -s '[:space:]' ',')

echo "UUID=$SRC_UUID"
echo "FEATURES=$SRC_FEATURES"
echo "BLOCK_SIZE=$SRC_BS"

[ -n "$SRC_UUID" ] && [ -n "$SRC_FEATURES" ] && [ -n "$SRC_BS" ] && echo SOURCE_INFO_OK
```

必须看到 `SOURCE_INFO_OK`；没有就停止，说明 `source-info.txt` 没读到或格式不对。

期望 `FEATURES` 类似：

```text
has_journal ext_attr resize_inode dir_index filetype extent 64bit flex_bg sparse_super large_file huge_file dir_nlink extra_isize metadata_csum
```

**不应出现 `orphan_file`。** 如果出现了，也照下面“完全复制源特性”的做法处理。

**也不应出现 `needs_recovery`。** 它表示源卡没有正常卸载；停止，回到 3.3 检查 `Filesystem state`，不要继续格式化目标卡。

### 4.3 清掉旧签名，建同特性 ext4

```bash
sudo wipefs -a "$TGT"
sudo mkfs.ext4 -b "$SRC_BS" -i 1048576 -L mu300sd \
  -O none,"$FEATURE_LIST" "$TGT"
```

说明：

- `-b "$SRC_BS"`：块大小与源卡一致（通常 4096）；
- `-i 1048576`：每 1 MiB 一个 inode，和安装器的 “one inode per 1024 KiB” 一致，避免 256GB 卡默认生成上千万个 inode；
- `-O none,...`：先清空默认特性，再逐个启用源卡的特性，**避免新版 mke2fs 偷偷加上 `orphan_file`**；
- `-L mu300sd`：label 必须一致。

**如果 `-O none,...` 报错**（个别 mke2fs 不接受 `none` 与其它特性混用），改用：

```bash
sudo mkfs.ext4 -b "$SRC_BS" -i 1048576 -L mu300sd -O ^orphan_file "$TGT"
```

如果连 `orphan_file` 都提示未知（说明 e2fsprogs 足够老、本来就不会开它）：

```bash
sudo mkfs.ext4 -b "$SRC_BS" -i 1048576 -L mu300sd "$TGT"
```

无论用哪种，下一步都必须做特性核对。

### 4.4 恢复 UUID 并核对特性

```bash
sudo tune2fs -U "$SRC_UUID" "$TGT"
sudo e2fsck -fy "$TGT"
sudo dumpe2fs -h "$TGT" 2>/dev/null | grep -E \
  'Filesystem volume name|Filesystem UUID|Filesystem features|Block count|Block size|Inode count'
```

特性对比（结果应为空）：

```bash
diff \
  <(echo "$SRC_FEATURES" | tr -s '[:space:]' '\n' | sort) \
  <(sudo dumpe2fs -h "$TGT" 2>/dev/null | awk -F': *' '/Filesystem features/{print $2}' | tr -s '[:space:]' '\n' | sort)
```

- **有差异就停止**，尤其目标卡多出 `orphan_file` 时，绝不能插回 F50；
- 目标卡应是 `LABEL="mu300sd"`，UUID 与源卡相同。

再显式核对 label 和 UUID：

```bash
[ "$(sudo blkid -s LABEL -o value "$TGT")" = "mu300sd" ] && echo LABEL_OK
[ "$(sudo blkid -s UUID -o value "$TGT")" = "$SRC_UUID" ] && echo UUID_OK
```

必须看到 `LABEL_OK` 和 `UUID_OK`。

### 4.5 挂载目标卡

```bash
sudo mkdir -p /mnt/new
sudo mount "$TGT" /mnt/new
findmnt /mnt/new
```

## 5. 解包与校验

### 5.1 解包

```bash
cd /mnt/new
sudo tar -xpf /mnt/c/f50-sd/rootfs.tar \
  --numeric-owner --xattrs --xattrs-include='*' --acls --sparse
df -h /mnt/new
sudo du -sx --block-size=1 /mnt/new
```

### 5.2 结构、权限、属主对比

```bash
sudo find . -xdev -printf '%P\t%y\t%m\t%U\t%G\t%l\n' \
  | LC_ALL=C sort > /mnt/c/f50-sd/target-manifest.txt

diff -u /mnt/c/f50-sd/source-manifest.txt /mnt/c/f50-sd/target-manifest.txt \
  && echo MANIFEST_OK
```

- 如果唯一差异是目标卡多了一个 `lost+found`，这是 `mkfs` 创建的，可以接受；
- 其他任何差异都停止，不要插卡启动。

### 5.3 逐文件 SHA-256 对比

```bash
sudo find . -xdev -type f -print0 \
  | LC_ALL=C sort -z \
  | sudo xargs -0 sha256sum > /mnt/c/f50-sd/target-sha256.txt

diff -u /mnt/c/f50-sd/source-sha256.txt /mnt/c/f50-sd/target-sha256.txt \
  && echo SHA256_OK
```

**必须看到 `MANIFEST_OK` 和 `SHA256_OK` 才能继续。**

### 5.4 （可选）原 SSH 私钥丢了？给新卡加一把新钥匙

如果原 WORK 的 `ssh-key` 已经找不到，但你还是想 SSH 核对，就在**卸载之前**做这一步：

```bash
ssh-keygen -t ed25519 -N '' -C dashplay-clone -f ~/.ssh/dashplay-clone
sudo mkdir -p /mnt/new/etc/dropbear
sudo sh -c 'cat ~/.ssh/dashplay-clone.pub >> /mnt/new/etc/dropbear/authorized_keys'
sudo chmod 600 /mnt/new/etc/dropbear/authorized_keys
sudo chown root:root /mnt/new/etc/dropbear/authorized_keys
```

启动后用 `ssh -i ~/.ssh/dashplay-clone root@100.96.0.1` 登录。原来的公钥不会被删；新钥匙只是追加。私钥在 WSL 的 `~/.ssh/dashplay-clone`，私有保存。

### 5.5 卸载、检查、断开

```bash
cd /
sync
sudo umount /mnt/new
sudo e2fsck -fy "$TGT"
sudo tune2fs -l "$TGT" | grep -E 'Filesystem volume name|Filesystem UUID|Block count'
```

PowerShell：

```powershell
usbipd detach --busid <目标 BUSID>
```

安全删除硬件，拔出 256GB 卡。

## 6. F50 实机验收

1. **给 F50 断电**，取出 512GB 原卡，插入 256GB 新卡；
2. 上电，等约 40–60 秒；
3. 预期：出现 WiFi `DVA`，iPhone 能连上，CarPlay 出画；
4. 如果进了原厂 Android，说明 Linux 启动失败——先断电，换回原卡确认机器正常，再排查新卡；
5. 用原安装的 SSH 私钥登录（特斯拉模式地址是 `100.96.0.1`）：

```bash
ssh -i <原 WORK>/f50/private/ssh-key root@100.96.0.1
```

如果还没切到特斯拉模式，试 `192.168.77.1`；密码在 `<原 WORK>/f50/private/openwrt-root-password.txt`。

如果原 WORK 的 `ssh-key` 丢了：可以用上面的 root 密码直接 SSH（OpenWrt 的 Dropbear 默认允许密码），也可以用 5.4 里给新卡加的新钥匙。两者都没有就跳过 SSH，先看 WiFi/CarPlay；下面的 `df`/`blkid` 核对建议做，但不是启动的必要条件。

在 F50 上执行：

```sh
df -h /
cat /run/mu300/linux-slot
blkid /dev/mmcblk1
grep mmcblk1 /proc/partitions
mu300-next-boot status
/etc/init.d/dashplay status
grep -E "CarPlay is live|session active" /var/run/dashplay/receiver.log | tail -5
```

应看到：

- `df -h /` 总容量约 238G（256GB 卡；可用空间约 226G）；
- `linux-slot` 为 `a`；
- `blkid` 显示 `LABEL="mu300sd"`，UUID 与源卡一致；
- `/proc/partitions` 里 `mmcblk1` 约 2.4–2.5 亿个 1K 块（约 238–256GB）；
- `mu300-next-boot status` 显示 `default boot: linux`；
- DashPlay `running`；
- iPhone 连接后 receiver 日志有 `CarPlay is live`。

再确认：

- iPhone **不用重新配对**就能连；
- 特斯拉模式、WiFi 名称/信道、认证文件都还在；
- 冷启动（拔电再上电）连续两次都正常进 OpenWrt。

验收通过后，**原卡至少保留一周**，不要格式化。`rootfs.tar` 含认证与配对数据，也要私有保存，不要外传。

## 7. 失败与回滚

- **新卡起不来**：断电，拔新卡，插回原卡，F50 应恢复原状。原卡全程只读，没有被修改。
- **新卡进了 Android**：多为卡接触不良、文件系统特性不兼容或根文件系统挂载失败。换回原卡后检查：
  - `lsblk` 是否整卡 ext4；
  - 目标卡特性是否与源卡完全一致（重点看 `orphan_file`）；
  - `MANIFEST_OK` / `SHA256_OK` 是否真的通过。
- **需要重做**：把新卡重新接入 WSL，从第 4.3 步开始（`wipefs` 会清掉重来），不要动原卡。
- **读卡器中途掉线**：重新 attach，删掉未完成的 `rootfs.tar`，从打包步骤重来；源卡不受影响。

## 8. 备选：在 256GB 卡上全新安装

只在克隆反复失败、且你手上有**原安装的完整 WORK 目录**时考虑。全新安装会清空 256GB 卡，但保留 512GB 原卡作备份。

**不要对已经克隆好的卡再跑 `f50-install.py openwrt`**：它会清空整张 SD 卡。

大致流程：

1. F50 断电，取出原卡，插入 256GB 卡；
2. 上电进原厂 Android（已 root），确认电脑能通过 USB 连上 Android 的 ADB；
3. 在 Windows 上用原 WORK 目录执行 `f50-install.py openwrt`，再按 skill 做 `dashplay`、认证、`tesla`；
4. DashPlay 认证文件在 Mac 的原 WORK 里，需要先复制过来；
5. iPhone 配对、WiFi/特斯拉设置需要重做。

**没有原 WORK 目录就不要走这条路**——`f50-install.py` 需要原来的 state、密钥和密码文件；缺了会卡在 `needs('flash')`。这种情况下先回原卡，我们再从 Mac 处理。

## 附录 B：常见问题

**Windows 弹“需要格式化”**
点取消。不要在磁盘管理里初始化或新建分区。`usbipd attach` 后 Windows 会释放这张卡。

**WSL 里 `lsblk` 看不到卡**
确认 `wsl -l -v` 是 VERSION 2；管理员 PowerShell 里 `usbipd list` 状态应为 `Attached`；`sudo dmesg | tail -30` 看内核是否识别；换 USB 口/读卡器。

**`wsl --install` 失败，或 WSL2 起不来**
确认 BIOS 里 Intel VT-x / AMD-V 已开启；Windows 功能里“虚拟机平台”和“适用于 Linux 的 Windows 子系统”已启用；再执行 `wsl --update`。

**`mount` 报 journal recovery**
不要对源卡执行 `e2fsck -y`。源卡是唯一能启动的系统，任何写入都可能破坏它。停止并保留现场。

**`mkfs.ext4` 报 `Unknown filesystem feature 'orphan_file'`**
说明当前 e2fsprogs 太老，本来就不会启用它；去掉 `-O ^orphan_file` 重新执行，然后仍然做 4.4 的特性对比。

**解包时报 `No space left on device`，但 `df` 显示还有空间**
是 inode 用完。回到 4.3，把 `-i 1048576` 改成 `-i 262144` 重做目标卡，再重新解包。

**新卡插回 F50 后进了 Android**
F50 连续启动 Linux 失败会回退 Android。先换回原卡确认机器正常；再检查新卡是否整卡 ext4、特性是否一致、label/UUID 是否正确。

**两块卡 UUID 相同，会不会冲突**
不会，因为 F50 只有一个卡槽，本方案也始终一次只接一张卡到 WSL。不要同时把两张卡接到同一台 Linux 上挂载。

**SSH 提示 host key 变化**
正常情况下不会——Dropbear 主机密钥在根文件系统里，已随克隆保留。如果提示，先确认你连的是 F50 而不是别的设备；确认后再按提示删除旧记录。
