# F50 接收端图标替换与「盒子设置」标签调查

- 日期：2026-11-05
- 设备：ZTE F50（SD 卡 OpenWrt + DashPlay，特斯拉模式，`100.96.0.1`）
- 范围：只改已安装接收端 jar 里的设置图标；不重建源码、不提交仓库
- 保密：本文件不含密码、私钥、认证文件、盒子标识；备份时间戳为当次实际值

## 一句话结论

车机上 CarPlay 主屏幕那个「盒子设置」图标来自接收端 jar 根目录的**资源文件** `f50-settings.png`，换掉这个资源并重启 `dashplay` 即可生效；而图标**下面的文字**是编译进 `CarPlayServer.class` 的**字符串常量**（`oemLabel`），不是资源，本次没有改。

## 一、图标：位置与生效方式

| 环节 | 事实 |
|---|---|
| 源码位置 | PlayPort 上游 `server/src/main/resources/f50-settings.png`（补丁 [playport-car-viewer.patch](../patches/playport-car-viewer.patch) 新增该文件） |
| 打包结果 | 位于 `server-0.1.0.jar` **根目录**，条目名就是 `f50-settings.png` |
| 加载方式 | 启动时一次读取：`javaClass.getResourceAsStream("/f50-settings.png")`，包进 `AirPlayIcon(180, 180, bytes)` |
| 上报方式 | 随 AirPlay 信息一起发给 iPhone：`oemIconVisible` / `oemIconLabel` / `oemIcons` |
| 尺寸约定 | 代码里固定声明 `180×180`，与实际字节尺寸无关——传错尺寸会「声明 180、内容不是」，所以脚本按 180×180 强校验 |
| 生效时机 | 进程启动时读取一次 → 必须重启 `dashplay`；重启盒子无额外作用 |

## 二、文字（oemLabel）：为什么不能只换文件

- 值在 `server/src/main/kotlin/com/playport/server/CarPlayServer.kt` 第 92 行附近：`oemLabel = "盒子设置"`（[playport-fullscreen-hint-box-label.patch](../patches/playport-fullscreen-hint-box-label.patch) 把原来的 `"设置"` 改成现在这样）。
- 编译后它是 `com/playport/server/CarPlayServer.class` 常量池里的一个 `CONSTANT_Utf8` 条目。
- 想改只能：① 改 class 字节（常量池条目是「长度 + 内容」，长度变化需同步改前缀，改完必须做完整结构校验）；或 ② 改补丁 + 完整重建接收端（Docker + JDK 25）。
- 本次**未执行**任何 class 改动，标签仍是「盒子设置」。

## 三、盒子上的运行时事实

- 安装目录：`/opt/dashplay/playport/server/build/install/server/lib/`，接收端为 `server-0.1.0.jar`；启动器 `launcher/onecloud-launcher.jar` 与 `lib/*.jar` 一起进 classpath。
- 服务：procd 管理的 `/etc/init.d/dashplay`（`stop` / `start` / `restart`），与 SSH 的 dropbear 相互独立——重启 `dashplay` 不会断开已有 SSH 会话。
- 盒子上有 `/usr/bin/python3`（procd 服务本身就在用），脚本以它执行。
- 该 jar **未签名**（无 `META-INF/*.SF|RSA|DSA`）；若将来签名，重写资源会导致 JVM 拒绝加载，脚本对这种 jar 直接报错。
- **AppCDS 无需手动清理**：`scripts/onecloud/run-receiver.py` 用「jar 名 + 体积 + mtime」做指纹，任一 classpath jar 变化就删除 `state/receiver/app-cds.jsa`。
- **升级行为**：DashPlay 升级会整体替换 `lib/`，图标恢复为项目自带那张，需要重新部署；OpenWrt 上的更新检查按**版本号**比较，哈希只用于诊断本地改动，所以被改过的 jar 不会让更新不可用。

## 四、传输：macOS 的 scp 为什么连不上

- 盒子是 Dropbear，没有 `/usr/libexec/sftp-server`；macOS 自带 OpenSSH 9 的 `scp` 默认走 SFTP，于是报 `ash: /usr/libexec/sftp-server: not found`。
- 两条可行路线：`scp -O`（强制旧协议），或干脆用 `ssh 'cat > 文件' < 本地文件` / `ssh | tar`。**部署脚本采用了 ssh + tar**，不依赖 sftp-server，也不依赖 `scp -O` 的版本。

## 五、本次新增的两个脚本

### 1. `scripts/icons/replace-f50-icon.py`（在盒子上跑）

与最初版本相比的加固点：

- jar 不再写死文件名：默认扫描安装目录 `lib/*.jar`，挑出**唯一**含 `f50-settings.png` 的那个；零个或多个（歧义）直接报错。
- 图标必须是 **180×180 PNG**，否则报错退出；非 PNG、缺 IHDR 同样拒绝。
- 已签名的 jar **直接拒绝**（原来只打印警告）。
- 先写 `.new` 并**重新打开校验**（`testzip`、条目列表一致、图标字节一致），通过后才 `os.replace`；异常时删除临时文件，原 jar 不会处于半成品状态。
- 保留原 jar 的权限位与属主（root 下 `chown`），保留 zip comment、条目顺序、manifest 位置、STORED 条目类型。
- 已经是这张图时输出 `already carries this icon; nothing to do`，重复执行无副作用。

### 2. `scripts/icons/deploy-f50-icon.sh`（在 Mac 上跑，一条命令到底）

```sh
./scripts/icons/deploy-f50-icon.sh                        # 默认 root@100.96.0.1 + 透明圆角版图标
./scripts/icons/deploy-f50-icon.sh --icon <另一张 PNG>     # 换用别的图（如圆角填满的 RGB 版）
./scripts/icons/deploy-f50-icon.sh --keep-stopped         # 换完不启动服务
./scripts/icons/deploy-f50-icon.sh root@192.168.77.1      # 指定地址（未切特斯拉模式时）
```

行为：ssh + tar 上传到 `/tmp` → 远端比对 jar 内图标的 sha256（相同则**不碰服务**直接退出）→ `stop` → 备份为 `server-0.1.0.jar.bak-YYYYmmddHHMMSS` → 调用上面的 python 脚本 → 复核 jar 内 sha256 与本地一致 → `start`。任何失败路径都用 `trap` 把服务拉起来，避免把车机晾在没服务的状态。

- 本地文件：`assets/icons/f50-settings.png`（**未跟踪**）、同名同字节的 `tesla-app-icon-180.png`，另有圆角填满的 RGB 备用版 `f50-settings-tesla-square.png`。
- 部署结果：jar 内图标 sha256 = `305278b7…895b5c1`，与本地一致；备份 `server-0.1.0.jar.bak-20261105172642`。
- 车机侧：用户确认**图标已变**；图标下方文字仍为「盒子设置」。
- 网页设置页里也有「盒子设置」字样，属于 web 资源，同样是另一套字符串，未改。

## 七、验证方式（脚本本身怎么被验证的）

- `replace-f50-icon.py`：用构造 jar（manifest 在首位、混合 STORED/DEFLATED）跑 20 项检查——正常替换、幂等、尺寸错误、签名 jar、缺资源、非 PNG、自动发现（含非 jar 文件与无关 jar）、多 jar 歧义、无候选、替换后 `testzip`/条目顺序/STORED 类型——全部通过。
- `deploy-f50-icon.sh`：用假 ssh（本地执行）、假 init 脚本和假 jar 跑 6 个场景——正常替换、重复执行不动服务、尺寸错误（退出码 1、jar 未变、服务已恢复）、`--keep-stopped`、图标路径不存在、主机不可达（服务完全没被碰）。

## 八、回滚与升级后重放

```sh
# 回滚（用实际备份名）
ssh root@100.96.0.1 'J=/opt/dashplay/playport/server/build/install/server/lib/server-0.1.0.jar; cp -p "$J.bak-20261105172642" "$J" && /etc/init.d/dashplay restart'

# 升级后重放
./scripts/icons/deploy-f50-icon.sh
```

反复部署会在 `lib/` 里累积 `.bak-时间戳` 文件，每份约等于 jar 体积，攒多了自行清理。

## 九、明确未做 / 风险

- **未改标签**：需要动 class 常量池或重建接收端，风险高于换图，用户选择「先不动」。
- **未进仓库**：Tesla 图标是第三方商标美术，`assets/icons/` 与 `scripts/icons/` 保持未跟踪状态；仓库声明「图标为原创、不使用第三方图标」，所以不把这张图做成补丁、不随发布分发。
- 车机若仍显示旧图标：先断开重连 CarPlay，仍不变则重启车机（车机会按资源地址缓存），与盒子无关。
- 若圆角在车机上显示成黑角：改用 RGB 填角版本，`./scripts/icons/deploy-f50-icon.sh --icon assets/icons/f50-settings-tesla-square.png`。
