# F50 设备名称与显示名调查（手机端「DashPlay」从哪来）

- 日期：2026-11-05
- 设备：ZTE F50（SD 卡 OpenWrt + DashPlay，特斯拉模式，`100.96.0.1`）
- 起因：iPhone → 设置 → 通用 → CarPlay 车载 → 我的车，条目名为 `DashPlay`，确认能否改
- 范围：只做调查与命令整理，**本次没有修改盒子上的任何文件**
- 保密：本文件不含密码、私钥、认证文件、盒子标识

## 一句话结论

「我的车」里的 `DashPlay` 是**盒子的蓝牙名**（iOS 在配对那一刻记下）。盒子上其实有三处互相独立的 `DashPlay`，来源、改法、升级后的命运各不相同；改名只需动一个常量，但**手机端要重新配对才会换名字**。

## 一、三个名字对照

| 手机上在哪看到 | 名字来源 | 改在哪 | 升级后 |
|---|---|---|---|
| CarPlay 车载 → 我的车；设置 → 蓝牙 | 蓝牙适配器别名 | `/opt/dashplay/platform_debian.py` 的 `BLUETOOTH_NAME`（第 40 行）+ `/opt/dashplay/board_zte_f50.py` 里私有 BlueZ 的 `bluez.conf` `Name=`（第 192 行） | 被覆盖 |
| 控制中心 → 音频输出；AirPlay 设备名 | 接收端 `deviceName` / `model` / `manufacturer` | `/opt/dashplay/run-receiver.py` 第 150 行 | 被覆盖 |
| 设置 → Wi-Fi 列表里的网络名 | OpenWrt 的 SSID | LuCI → Network → Wireless | **保留**（属于系统配置） |

## 二、蓝牙名（本次确认的那一个）

机制：

- `platform_debian.py` 顶部 `BLUETOOTH_NAME = "DashPlay"`；`power_bluetooth()` 每次启动执行 `bluetoothctl system-alias $BLUETOOTH_NAME`。源码注释写明原因：BlueZ 默认用主机名（`onecloud`）命名适配器，而 iPhone 列在蓝牙里的就是这个别名。
- F50 用的是私有 D-Bus + 私有 BlueZ（`board_zte_f50.py` 生成 `bluez.conf`，其中 `Name=DashPlay` 是默认名）；别名会覆盖默认名，但两处保持一致更稳。
- 私总线地址：`/var/run/dashplay/bluetooth/system_bus_socket`（`RUN=/var/run/dashplay`，`BUS=RUN/bluetooth`）。

改法（在盒子上执行；`NAME` 换成想要的名字）：

```sh
cd /opt/dashplay
cp -p platform_debian.py platform_debian.py.bak
cp -p board_zte_f50.py  board_zte_f50.py.bak

NAME='我的盒子'
sed -i "s/^BLUETOOTH_NAME = \"DashPlay\"/BLUETOOTH_NAME = \"$NAME\"/" platform_debian.py
sed -i "s/Name=DashPlay/Name=$NAME/" board_zte_f50.py

/usr/bin/python3 -m py_compile platform_debian.py board_zte_f50.py && echo "syntax ok"
/etc/init.d/dashplay restart

sleep 20
DBUS_SYSTEM_BUS_ADDRESS=unix:path=/var/run/dashplay/bluetooth/system_bus_socket \
  bluetoothctl show | grep -E '^\s+(Name|Alias):'
```

判断标准：`Alias:` 变成新名字即成功；`Name:` 还是旧值不影响，iPhone 看的是 `Alias`。

## 三、手机端为什么要重新配对

iOS 在**配对时**记录配件名字，之后适配器改名，「我的车」里的旧条目不会跟着变。要换名字必须清掉旧配对：

1. iPhone → 设置 → 通用 → CarPlay 车载 → 旧条目 → 忽略此车
2. iPhone → 设置 → 蓝牙 → 该设备 ⓘ → 忽略此设备
3. 盒子设置页（`http://100.96.0.1:18080/` 或 `http://dashplay.lan/`）→ 打开配对窗口
4. iPhone 停在「设置 → 蓝牙」页面（iPhone 只有在蓝牙页才对外可发现）
5. 盒子设置页确认选中这台 iPhone，完成配对

时长限额（`scripts/onecloud/pairing_window.py`）：打开窗口后 180 秒内等待配对开始，单次尝试 120 秒，整轮上限 600 秒；超时重新点一次。

**重配对期间 CarPlay 不可用**，别在行车途中操作。可以先只改名 + 重启，再回手机看一眼——部分 iOS 版本会在配件重新广播后刷新列表标题，能刷新就免去重配。

## 四、AirPlay 名（另一个「DashPlay」）

- 值在 `run-receiver.py` 第 150 行硬编码：`"deviceName": "DashPlay", "model": "DashPlay", "manufacturer": "DashPlay"`。
- 该脚本**每次启动都会重写** `state/receiver/config.json`，所以直接改 `config.json` 无效，必须改脚本本身。
- 改完 `py_compile` 校验再重启，用 `grep -n deviceName /opt/dashplay/state/receiver/config.json` 回读确认。

## 五、Wi-Fi 名（第三个「DashPlay」）

- 来源是 OpenWrt 的 SSID：supervisor 通过 `ubus` 读 OpenWrt 的 Wi-Fi 名/密码/信道，写成交接文件 `state/hotspot.json` 给接收端。
- 改在 LuCI → Network → Wireless；DashPlay 自己的设置页只显示、不改网络。
- 改 SSID 会断开所有设备（iPhone、特斯拉、电脑），特斯拉还要再确认一次「行驶中保持连接」。
- 这条是系统配置，**升级不会回退**。

## 六、不要动的地方

- `scripts/onecloud/boxnet.py` 里证书 `/CN=DashPlay`：给车机浏览器签的证书，改名要重签，与手机显示名无关。
- web 页面标题 `· DashPlay`（`patches/playport-viewer-tesla.patch`）与媒体会话 `artist: 'DashPlay'`：属于车机浏览器页面，不是手机上的名字。
- CarPlay 图标下方的「盒子设置」是另一个东西（编译进 class 的 `oemLabel`），见 [F50-接收端图标替换-2026-11-05.md](F50-接收端图标替换-2026-11-05.md)。

## 七、备份、回滚与升级

```sh
# 回滚（改名前已备份）
cd /opt/dashplay && cp -p platform_debian.py.bak platform_debian.py && \
  cp -p board_zte_f50.py.bak board_zte_f50.py && /etc/init.d/dashplay restart
```

前两处（蓝牙名、AirPlay 名）都是程序文件，**升级会被覆盖**；SSID 不会。要长期保留只能走仓库层面：改 `scripts/onecloud/` 的源码/补丁，再按正常流程打包安装，而不是只改盒子。
