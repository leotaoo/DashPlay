# F50 系统结构与后台问答整理

- 日期：2026-11-03
- 设备：ZTE F50（原厂 B16）→ SD 卡 OpenWrt + DashPlay
- 性质：安装前答疑整理，配套 [F50-特斯拉-安装配置-2026-11-03.md](F50-特斯拉-安装配置-2026-11-03.md) 阅读；本文依据仓库代码与 [SKILL.md](SKILL.md) 核对，不含任何凭据或设备标识

## 一句话结论

F50 上是**同一个 SoC 上的两套 Linux 系统**：`boot_b` 是原厂 Android（自带 `192.168.0.1` 后台），`boot_a` 从 SD 卡启动 OpenWrt（`192.168.77.1` → 特斯拉模式后 `100.96.0.1` 的 LuCI 后台），`misc` 里 32 字节决定这次通电走哪个。两套互斥，同时只有一个在线。

## 一、两套系统的对照

| | 原厂系统 | SD 卡上的 OpenWrt |
|---|---|---|
| 本质 | Android（Linux 内核 + Android 用户空间） | OpenWrt（Linux 内核 + musl/busybox/procd/apk/LuCI） |
| 内核 | Linux 5.4（展锐厂商 BSP） | 同样 5.4（厂商基线，不是主线 6.x） |
| 后台 | `http://192.168.0.1/` | `http://192.168.77.1/` → 特斯拉模式后 `http://100.96.0.1/`，另有 `http://dashplay.lan/` |
| 后台功能 | 运营商/APN、原厂 Wi-Fi、USB 共享等 | 网络、Wi-Fi、DHCP、防火墙、插件（含「服务 → DashPlay」） |
| 包/应用 | Android APK、Magisk 模块 | `apk`（Alpine apk-tools）软件包 |
| 用户数据 | `/data` 约 27 GiB，安装过程从未写入 | SD 卡 |

## 二、刷机后还有网页管理后台吗

**有，那是 OpenWrt 的 LuCI。** F2 装的是完整的 `openwrt-luci` 镜像（`scripts/f50-install.py` 里 `MU300_BOOT_OS=openwrt-luci`），F3 只是在它上面加装 DashPlay 插件，LuCI 与网络栈原封不动。

### 地址与登录

| 阶段 | 地址 |
|---|---|
| F2 刚装完（特斯拉模式之前） | `http://192.168.77.1/` |
| 启用特斯拉模式后（`br-lan` 改为共享地址段） | `http://100.96.0.1/` |
| 固定名称 | `http://dashplay.lan/` |

- 用户名 `root`；密码是安装时生成的，不是原厂的 `1234`，保存在电脑 `$WORK/f50/private/openwrt-root-password.txt`（权限 0600），**不贴进聊天**。
- 安装脚本同时把本机 SSH 公钥写入设备，之后 `ssh -i "$WORK/f50/private/ssh-key" root@100.96.0.1` 免密登录。
- 密码丢了不影响：用密钥登录后 `passwd` 重设。

### Wi-Fi 在哪里改

- **LuCI → Network → Wireless**（`/cgi-bin/luci/admin/network/wireless`）：SSID、密码、频段、信道、国家、发射功率。
- **DashPlay 自己的设置页**（`http://<盒子地址>:18080/`）**故意不改网络**，任何改网络的请求都会被拒绝（提示「网络在 OpenWrt 后台设置」）。它只显示「交给 iPhone 的 WiFi」并给一个跳到 LuCI 无线页的链接，链接按当前主机名生成，地址变了也跟着变。
- 改完 Wi-Fi 后 DashPlay 会通过 `ubus` 自动跟上（README：「WiFi 改了自动跟上」），**不需要重装或重新配对**。

### 四个注意点

1. 改 SSID/密码会断开所有设备（iPhone、特斯拉、电脑），要用新凭据重连；特斯拉还要再确认「行驶中保持连接」。
2. **不要随意改 `100.96.0.1`**：共享地址段是为了绕开特斯拉对 `192.168.x.x` 局域网地址的拦截。改了的话后台地址、画面地址、SSH 目标一起变。
3. 信道有讲究：CN/149 是特斯拉实车验证过的组合，36 在车机上看不到；5 GHz 搜不到就退到 2.4 GHz 信道 6。
4. 若选了默认启动原厂（选项 B）或 OpenWrt 连续 5 次起不来自动回退，此时只有 `192.168.0.1` 的原厂后台，没有 LuCI。

## 三、原厂后台（192.168.0.1）还能访问吗

**能，但只有在盒子启动原厂系统时。** 原厂后台是 Android 系统里的管理服务提供的网页，OpenWrt 运行时没有这套程序在响应。

- **原厂系统没被破坏**：F1 只写 `boot_b`、`trustos_b` 做 root；F2 只写 SD 卡、`boot_a` 和 32 字节 `misc`，并回读确认 `boot_b` 未变。Android 用户数据从未写入，所以原厂的 Wi-Fi 名称、密码、运营商/APN 设置都还在。
- 两边的 Wi-Fi 配置**互相独立**：LuCI 里改 SSID 不影响原厂，反之亦然；要一致得分别设。

### 切换命令

切到原厂（在 OpenWrt 上执行）：

```sh
ssh root@100.96.0.1 'mu300-next-boot android && reboot'
```

切回 OpenWrt（原厂系统下，需要电脑 + USB 线）：

```sh
adb connect 192.168.0.1:5555
adb -s 192.168.0.1:5555 shell sh /data/adb/modules/mu300_linux_switch/switch.sh
```

这次切换是一次性的，下次通电又回原厂；想以后都默认 OpenWrt，回到 OpenWrt 后再执行 `mu300-next-boot linux`。

### 对本次安装的建议

车里没有电脑，所以收尾检查时选 **A（默认 OpenWrt）**：上车通电自动出 CarPlay，把「回原厂后台」当成在家插线的操作。选 B 则原厂后台常驻，但每次用 CarPlay 都得先用电脑切过去，车上不可用。

### 两个风险

1. 原厂系统启动时，root 打开的 **ADB 5555 不验证客户端**，连上 F50 热点的任何人都能完全控制它——别在公共场所停在这套系统里，用完就切回。
2. `/data`（约 27 GiB）**不在备份范围内**（备份只覆盖 69/75 个分区，约 3.3 GiB）。将来若用原厂后台「恢复出厂设置」重建，自定义的 Wi-Fi 名/密码会丢，所以 F1 之前先记录原厂改过的设置。

## 四、原厂系统确实是 Android

| 证据 | 位置 |
|---|---|
| `getprop ro.build.display.id` 必须含 `F50_FLYMODEM_ZYV1.0.0B16` | `scripts/f50-install.py`（`getprop` 四项校验） |
| `ro.boot.slot_suffix` = `_b`、`sys.boot_completed` = `1` | 同上 |
| Magisk 给 `boot.img` 打补丁：解 lz4 压缩 ramdisk、校验 boot header | `scripts/prepare-f50-root-candidate.py` |
| `overlay.d/f50-access.rc`、`seclabel u:r:init:s0` | 同上（Android init 服务定义与 SELinux 标签） |
| `/data/adb`、`magisk --install-module` | `scripts/f50-install.py`（F2） |
| 分区 `boot_a/boot_b`、`misc`、`trustos_a/b`、`/data` | 备份与写入清单 |

补充：这是**设备形态的 Android**——没有桌面、没有应用商店、没有常规手机交互；能看到的原厂界面只有 `192.168.0.1` 的网页后台。Root 唯一带来的变化是多了一个 `su` 和一个不验证客户端的 ADB 端口。

## 五、OpenWrt 也是 Linux，只是内核基线是厂商的

OpenWrt 本身就是一套 Linux 发行版；Android 也是 Linux 内核 + Android 用户空间。所以「两套系统」= 两个 Linux 系统，区别在用户空间和内核构建基线，不是两个内核家族。

- F50 没有可用的主线移植（Wi-Fi、4G 模组、蓝牙都得厂商驱动），所以镜像是「新的用户空间 + 老的 5.4 内核」。
- F2 会硬校验 `DISTRIB_RELEASE` 为 25.12、`uname -r` 为 5.4、槽位为 `a`，不符就停止。
- **不能从官方源装内核模块**：官方 `kmod-*` 是给 6.12 编译的。这也是为什么不能在 F50 上 `apk add bluez-daemon`（会带入 6.12 的 `kmod-bluetooth`），蓝牙改由私有 BlueZ 承担（`scripts/onecloud/board_zte_f50.py`，运行时在 `/opt/dashplay-bluez`）。
- 实操含义：升级用户空间软件包（`apk`）没问题，换内核、随手加驱动基本不现实。

## 六、安装过程里的 `.apk` 要分清

同一个后缀，两个完全不同的生态，只是缩写撞车。

### 1. Android APK（当压缩包拆零件，从不安装）

| 文件 | 来源 | 用途 |
|---|---|---|
| `Magisk_28103.apk` | Xio-Shark/f50-b16 发布，`downloads.json` 固定 SHA-256 | F1 打 root：脚本以 zip 方式打开，取出 `lib/arm64-v8a/libmagisk.so`、`libbusybox.so`、`libmagiskboot.so`、`libmagiskinit.so`、`libmagiskpolicy.so` 及 `assets/boot_patch.sh`，拼进 `boot.img` 的 ramdisk，生成 `boot-root.img` 写入 `boot_b` |
| `DiPlay-*.apk` | DiPlay 发布列表（含预发布），按发布 API 的 SHA-256 摘要核对 | F3 取认证文件：只取 `assets/offline-mfi/identity.pk8` 和 `certificate.p7b`，并记录 `source.json` |

两点细节：

- 基础镜像 `magisk.img` 里带有第三方写入的 `overlay.d/adbip.rc` 和 `overlay.d/sbin/start_adbip.sh`，脚本会先删掉这两项，只保留经过审查的 Magisk 本体。
- 这两个 APK **都没装进任何设备**，F50 上也没有可安装应用的入口。

### 2. OpenWrt 的 apk（真正被安装）

OpenWrt 从 25.x 起用 Alpine 的 **apk-tools** 取代 `opkg`，包后缀同样是 `.apk`。F3 装的是四个：

| 包 | 内容 |
|---|---|
| `dashplay-*.apk` | 接收端主程序 |
| `dashplay-jre-*_aarch64_generic.apk` | Java 运行时（约 225 MB 的主要部分） |
| `luci-app-dashplay-*.apk` | LuCI 里的「服务 → DashPlay」 |
| `luci-i18n-dashplay-zh-cn-*.apk` | 中文翻译 |

安装命令形如：

```sh
apk update && apk add --allow-untrusted /tmp/dashplay-jre-*.apk /tmp/dashplay-2*.apk /tmp/luci-*.apk
```

- `apk update` 需要盒子能上网（F50 插 SIM 卡），依赖（Python 等）来自 OpenWrt 官方源。
- 项目自己打的包没有签名，所以必须 `--allow-untrusted`。

### 3. 为什么容易混

- **apk** = **A**lpine **P**ackage **K**eeper（Alpine / OpenWrt 用）
- **APK** = **A**ndroid **P**ackage **K**it（Android 用）

两者格式、目的完全无关，只是都缩写成 "apk"。

**总结**：F50 上从头到尾没有安装过任何 Android 应用；两个安卓 APK 只是被拆开当零件用（一个做 root 镜像、一个取 CarPlay 认证文件），真正装进系统的是 OpenWrt 自己的 apk 软件包。

## 七、速查

| 问题 | 答案 |
|---|---|
| 刷机后还有网页后台吗 | 有，OpenWrt 的 LuCI |
| LuCI 地址 | 装完 `192.168.77.1`；特斯拉模式后 `100.96.0.1`；或 `dashplay.lan` |
| Wi-Fi 在哪设 | LuCI → Network → Wireless；DashPlay 设置页只显示、不改 |
| 改 Wi-Fi 要重装吗 | 不要，DashPlay 自动跟上 |
| 原厂后台还在吗 | 在，但只在启动 Android 时；需电脑+USB 切换 |
| 原厂系统是什么 | Android（Magisk root 那套流程） |
| OpenWrt 是 Linux 吗 | 是；内核为厂商 5.4 基线，不能装官方 6.12 的 kmod |
| 安装包里的 .apk | 两个安卓 APK 只当压缩包；真正安装的是 OpenWrt 的 apk 包 |
