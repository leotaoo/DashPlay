# F50 刷机跑 CarPlay 的原理

- 日期：2026-11-03
- 对象：ZTE F50（原厂 B16）→ SD 卡 OpenWrt → DashPlay 接收端
- 配套：[F50-特斯拉-安装配置-2026-11-03.md](F50-特斯拉-安装配置-2026-11-03.md)、[F50-系统结构与后台-2026-11-03.md](F50-系统结构与后台-2026-11-03.md)
- 说明：本文依据仓库代码与补丁整理，不含任何凭据、密钥或设备标识

## 一句话原理

把一台 4G 随身路由改造成「CarPlay 接收端」：iPhone 先在蓝牙上被引导连上 F50 的 Wi-Fi，然后用 CarPlay（AirPlay）协议把画面、声音和反向的触控/麦克风交给 F50；F50 再把画面转成一网页，车机浏览器打开就能看、能点。

```
   ┌──────────┐   蓝牙 iAP2：SSID/密码/信道     ┌───────────────┐
   │ iPhone   │ ───────────────────────────────► │ ZTE F50        │
   │          │ ◄── Wi-Fi：CarPlay 视频/音频 ─── │ （OpenWrt +    │
   │          │ ── 触控/滚轮/麦克风 ──────────► │  DashPlay）    │
   └──────────┘                                  └───────┬───────┘
                                                         │ HTTPS + WebSocket
                                                         ▼
                                                  ┌───────────────┐
                                                  │ 车机浏览器      │
                                                  │ 画面 / 触控     │
                                                  └───────────────┘
```

画面和声音只在 iPhone 与 F50 之间传，**不经外网、不耗流量**；F50 插的 SIM 卡只用于车机自带应用（特斯拉音乐、地图）上网。

## 一、为什么必须刷机

原厂那套是「上行路由」：Android 系统负责把 4G 转成 Wi-Fi，管理界面只做网络设置。它缺三样东西：

| 缺什么 | 后果 |
|---|---|
| 没有 CarPlay 接收端程序（PlayPort） | 无法与 iPhone 建立 CarPlay 会话 |
| 没有可编程的蓝牙/Wi-Fi 控制（非 root、无 BlueZ 权限） | 无法自动做蓝牙引导与 Wi-Fi 交接 |
| 没有 Java 21 / 包管理 | 装不了接收端及其依赖 |

而 F50 的 USB 口不是主机口，**iPhone 插不了线**，所以只能走无线 CarPlay——这条路线正好完全依赖「蓝牙引导 + Wi-Fi 会话」，于是选中它。

路线因此是：保留原厂 Android（可随时回退）→ 用 Magisk 给它打 root → 在 **SD 卡**上装一套 OpenWrt（有包管理、LuCI、Python、Java、BlueZ）→ 把 DashPlay 作为 OpenWrt 插件装上。

## 二、启动链：一台机器两个系统

展锐（Unisoc）平台的启动顺序：

```
BootROM → FDL 下载模式（USB 1782:4D00，刷机/备份走这里）
        → bootloader
        → 读 misc 里 32 字节决定这次启动哪个槽
             ├─ boot_a → OpenWrt（内核在分区里，根文件系统在 SD 卡）
             └─ boot_b → 原厂 Android（被 Magisk 打过补丁）
```

| 分区 | 作用 | 安装过程是否写入 |
|---|---|---|
| `boot_a` | OpenWrt 的启动镜像 | F2 写 |
| `boot_b` | 原厂 Android 的启动镜像（rooted） | F1 写（Magisk 补丁） |
| `trustos_a/b` | 展锐 TEE，root 流程会用到 | F1 写 |
| `misc` | 32 字节控制「默认启动哪个槽」 | F2 写 |
| SD 卡 | OpenWrt 根文件系统 | F2 写（清空） |
| 用户数据 `/data` | 原厂 Android 的设置与数据 | **从不写** |

- `mu300-next-boot linux/android` 改的就是 `misc`；连续 5 次起不来会自动回安卓（不 lock）。
- 用 SD 卡而不是 eMMC，是为了让原厂系统保持完整可回退；代价是少了 8 GB 以上的卡。

## 三、接收端软件栈（OpenWrt 层）

```
procd
 └─ dashplay (supervisor_openwrt.py)          主控：读网络、起接收端、管蓝牙、管设置页
     ├─ board_zte_f50.py                      F50 蓝牙：rfkill 复位 → 厂商初始化 → 私有 BlueZ/D-Bus
     ├─ run-receiver.py                       生成配置与令牌，启动 Java
     │   └─ Launcher.java → PlayPort 服务端   CarPlay/AirPlay 协议实现（Kotlin）
     └─ settings_page.py                      设置页（OpenWrt 上是 18080，80 归 LuCI）
```

几个关键点：

- **网络来源**：supervisor 通过 `ubus` 读 OpenWrt 的 Wi-Fi 名、密码、信道、加密方式，写成交接文件（handoff）交给接收端；LuCI 里改了 Wi-Fi，DashPlay 自动跟上。
- **端口**：AirPlay/RTSP 监听 `7000`；网页在 `18443`（HTTPS）；设置页在 `18080`（LuCI 占着 80）。
- **网页证书**：盒子自己生成 CA 和叶证书（`state/tls/`），所以车机第一次打开会提示不安全；设置页可下载 `ca.crt` 装到车机上消警告。
- **令牌**：接收端生成 32 位十六进制 token 写进网页目录，页面加载后用它连 WebSocket——只允许盒子自己的页面拿到，避免任意网页盗用。
- **F50 的蓝牙是难点**：内置 Marlin3 控制器（`/dev/ttyBT0`）没有默认地址、还会软阻塞；脚本先按厂商顺序上传 PSKey/RF 数据，再拉起一整套**私有 BlueZ**（`/opt/dashplay-bluez`），不往系统里装 `bluez-daemon`——因为官方源的包会带入和 5.4 内核不匹配的 `kmod-bluetooth`。

## 四、CarPlay 怎么建立起来

### 1. 预先配对（一次）

设置页「添加 iPhone」走 BlueZ 的交互式配对，配对码要在 iPhone 上人工核对。配对信息留在盒子，之后自动连。

### 2. 广播与监听

接收端用 mDNS（JmDNS）广播 AirPlay 服务，同时 RTSP 在 7000 端口监听——这就是开机日志里 `RTSP listening` 那一行。

### 3. 蓝牙引导（wireless bootstrap）

`linux/bt-bridge/bt-bridge` 通过 BlueZ 的 Profile API 以 **iAP2** 客户端角色建立 RFCOMM 连接，把 **Wi-Fi 名称、密码、信道、加密方式**交给 iPhone。日志：`wireless bootstrap: iPhone=… hostBt=… wifi=… ch=…`。

> 这里有一个必须的补丁：`patches/playport-process-byte-stream.patch`。原实现的分段读取会把剩余数据排到后续块之后，破坏 iAP2 字节顺序，握手会失败；补丁保留顺序并稳定返回 EOF。

### 4. Wi-Fi 交接与会话

iPhone 收到凭据后自己连上 F50 的 Wi-Fi（拿 DHCP），随后接收端发出 CarPlay 邀请 → iPhone 接受 → `CarPlay session active` → `CarPlay is live`。这几个里程碑就是排错时看的日志关键字。

### 5. MFi 身份校验

iPhone 只与「能出示有效配件证书、并用对应私钥签名」的接收端建会话。所以必须有这一对文件：

```
identity/offline-mfi/identity.pk8       # PKCS#8 EC P-256 私钥
identity/offline-mfi/certificate.p7b    # 对应证书
```

它们是**共享的实验身份**（来自公开的 Carlinkit 固件），不是签发给本项目的；Apple 可能随时让它失效。安装时用 OpenSSL 验证「私钥与证书公钥配对」，通过才写入盒子。

### 6. 会话里的四条数据流

| 方向 | 内容 | 用途 |
|---|---|---|
| iPhone → 盒子 | H.264 / H.265 视频帧（NALU） | 车机看到的画面 |
| iPhone → 盒子 | 音频流（导航播报、媒体） | 声音 |
| 盒子 → iPhone | 触控、方向键、滚轮、焦点 | 在车机网页上操作 |
| 盒子 → iPhone | 麦克风（浏览器采集） | 打电话、Siri |

## 五、从 CarPlay 流到网页：DashPlay 改了什么

PlayPort 原生是把画面渲染到本机窗口；DashPlay 通过一系列补丁把它改成「网页接收端」：

| 补丁/组件 | 作用 |
|---|---|
| `playport-web-host.patch`、`playport-own-page-http2.patch` | 内置网页服务与自带页面，不再依赖外部页面 |
| `playport-viewer-access-own-page.patch` | token 只对盒子自己的页面有效 |
| `playport-decode-backlog.patch`、`playport-viewer-lag-gate.patch` | 解码积压时丢帧追最新，避免越看越延迟 |
| 视频通路 | 每帧封成 `videoFrame(type, keyframe, nalu)` 经 **WebSocket** 广播，浏览器用 **WebCodecs `VideoDecoder`** 解码上屏（支持 H.265 时自动切） |
| 音频通路 | 实时音频用 `AudioDecoder`；**音乐走 MSE**（`MediaSource` + `audio` 元素），有线可给无损 48 kHz FLAC |
| `playport-viewer-*` 系列 | 车机体验：等比适配、换窗口尺寸重连、稳态画面、夜间、统计与调试 HUD |
| `playport-audio-*`、`playport-tesla-audio-split.patch` | 多路音频分离与路由（网页 / 车机蓝牙） |
| `playport-idle-release.patch` | 没有网页在看的 N 秒后主动结束无线会话（默认 300 s） |

也就是说：**盒子不做视频转码**，它把 iPhone 发来的编码帧原样转发给浏览器，由车机浏览器自己硬解——这是能在车机这种弱算力设备上跑顺的关键。

## 六、特斯拉模式额外做了什么

特斯拉的浏览器和网络都有额外限制，所以 `tesla` 开关不是「换个皮肤」，而是四件事：

| 问题 | 处理 |
|---|---|
| 特斯拉不让打开 `192.168.x.x` 这类私网地址 | 局域网改用 `100.96.0.1/24`（RFC 6598 运营商共享地址段），并给车机下发正确的网关/DNS |
| 连上无外网的 Wi-Fi 就弹「无互联网连接」 | 无上游时由盒子代答特定域名的联网检查（nft + dnsmasq 定向应答）；**插卡有真网时反而关掉**，避免误判 |
| 音乐/通话会和在页面上播放的声音打架 | `callsAndSiri=false`：接收端不提供通话与 Siri 音频、也不提供麦克风，让 iPhone 继续用车机蓝牙；页面不显示歌曲信息、不接管媒体键 |
| 车机浏览器不理会网页的全屏请求 | 全屏按钮借「白名单视频站点」跳转链（v.qq.com → 1905.com → 回到本页）来获得全屏 |

导航播报仍走网页（按 `default` 音频类型，页面侧做增益与限幅）；麦克风增益在特斯拉上降到 4（车机麦克风本来就响）。

## 七、一次上车的时序

| 阶段 | 现象 | 参考耗时 |
|---|---|---|
| 通电 | 读 `misc` → 起 OpenWrt | — |
| OpenWrt 起来 | supervisor 就绪、蓝牙初始化 | 一段启动时间 |
| 接收端 | `RTSP listening`、mDNS 广播 | — |
| 引导 | 蓝牙连上已配对 iPhone、发 Wi-Fi 凭据 | `invitation sent` |
| 交接 | iPhone 连上 Wi-Fi、接受邀请 | `session active` |
| 出画 | 日志 `CarPlay is live` | F50 整机约 37–44 s |
| 车机打开网页 | 浏览器访问 `https://<盒子地址>:18443/` | — |
| 离开/回来 | iPhone 离开 Wi-Fi 不再邀请，连回约 4 s 恢复 | — |

## 八、这条路的约束与代价

1. **身份是共享的**：不是 Apple 签发，iOS 更新随时可能失效；不能转发、不能上传。
2. **只能无线**：F50 的 USB 口不是主机口，插不了 iPhone。
3. **内核锁在 5.4**：厂商 BSP，官方源的 `kmod-*`（6.12）一个都不能装；蓝牙只能带私有 BlueZ。
4. **信道敏感**：5 GHz 要能开在被支持的信道（国内特斯拉实测 149 可见，36 看不到）；退回 2.4 GHz 会明显变慢。
5. **改启动分区有变砖风险**：断电或写错可能需要拆机短接；备份和回读校验就是为这个准备的。
6. **声音的边界**：导航播报走网页；电话和 Siri 在特斯拉模式下由车机蓝牙承担。若 iPhone 同时连着车机自带蓝牙又在网页里通话，会互相占麦克风。

## 九、术语

| 词 | 含义 |
|---|---|
| CarPlay / AirPlay | Apple 的车载投屏协议族；CarPlay 会话跑在 AirPlay 之上 |
| iAP2 | Apple 配件协议，这里经蓝牙 RFCOMM 用来传 Wi-Fi 凭据 |
| MFi 身份 | 配件证书 + 私钥，iPhone 用它确认「你是合法配件」 |
| RTSP | 会话控制通道（端口 7000），建会话、传控制指令 |
| mDNS | 局域网服务发现，接收端靠它被 iPhone 找到 |
| NALU | H.264/H.265 的视频帧单元，网页按帧解码 |
| WebCodecs | 浏览器直接调用硬解码的 API（视频/音频） |
| MSE | MediaSource Extensions，音乐/媒体用缓冲播放 |
| LuCI | OpenWrt 的网页后台 |
| ubus | OpenWrt 的内部总线，supervisor 用只读方式取网络配置 |
| Magisk | Android 的 root 方案，F1 用它给 boot 打补丁 |
| FDL | 展锐芯片的 USB 下载模式，备份与刷写走它 |
| TrustOS | 展锐的可信执行环境分区，root 镜像会用到 |
